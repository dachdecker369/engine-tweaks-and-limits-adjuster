# Plan

The order of work for a change to TweaksV, phase by phase, each phase ending with the test suites green, the four builds (Release, Debug, the test build, the analysis build) clean, a local commit and my boot. It carried the decals part of 1.6.0, the whole rewrite of 2.0.0, the fixes of the 2.0.0 audit and the 2.1.1 patch for T-UNLOCK (all in the git history). Two versions are planned, in this order: 2.2.0, the DirectStorage part redesigned to free the files instead of refusing them; 2.2.1, the RageOpenV and StraightToStoryMode parts switching themselves off next to NaturalVision Enhanced's loader. Both come from a player's report, a crash with NVE installed; [ROADMAP.md](ROADMAP.md) holds their design and the findings behind it.

## How the work runs

Each version is a track: one coding session in a worktree of its own (the app makes it under `.claude\worktrees\` with a `claude/...` branch), with a prompt from the overview session, kept in `.claude\prompts\` and never committed. A track owns its files and regions, so two tracks never touch the same region of a file; where a line is shared all the same - the check count in NOTES.md and in SPECIFICATIONS.md 14.1, the adjacent rows of 14.2, the RageOpenV row of 4.3 - the overview session resolves the merge. A track commits on its branch only, each item its own commit; it never merges, tags, pushes or sets the version; after every commit it writes its paragraph into the State block below and a two-line report into the chat, and it ends its turn only when the track is done or a decision of mine blocks everything left. The overview session rebases the branches onto main in order, makes the changelog lines and the check count one, sets the version, runs the suites from a clean rebuild, hands me the boot, then tags and pushes main and the tag together. Track 1 (2.1.1) is done and released; track 2 starts now, because it rewrites the file track 1 changed; track 3 ran in parallel with track 1 and is released after 2.2.0.

## 2.2.0 - the DirectStorage part frees the files instead of refusing them (track 2)

The design is in [ROADMAP.md](ROADMAP.md), with D1 decided: the sharing is decided in the `NtCreateFile` hook alone, by the open's own path, access and sharing. Track 2 is under way. One phase:

1. `TweaksVDirectStorage.cpp`: the `NtCreateFile` hook, today made with `DIAGNOSTIC_MODE` for the log, is made whenever `UNLOCK_FILES` is on, at start-up, and does the job. An open of a file inside the game folder - not a directory, not through a RootDirectory handle, the path readable and made full as the hook does today - that is not `.rpf` or `.cache`, asks for read access only (no write, append or delete access) and already shares reading gets `FILE_SHARE_WRITE` and `FILE_SHARE_DELETE` added before the call goes on; every other open goes on untouched. A hook that cannot be made is a problem of the start-up summary (`The files in the game folder are not unlocked this session: NtCreateFile could not be hooked (details in TweaksV.log).`). The `OpenFile` hook refuses nothing any more: the factory and `OpenFile` hooks are made with `DIAGNOSTIC_MODE` only, as aids, and a factory request that never comes within 30 seconds is a diagnostic line (T-DIAG). The summary 10 seconds after the first open counts, from the `NtCreateFile` hook, the opens widened and the files they belong to, by type, and the opens in the game folder left as they were, by reason (an archive, a write open, an exclusive open, a directory, a path not readable or relative) - each call in one count, so the figures add up. Every new kind of line that comes per event stops at the 20,000-line cap. `DirectStorageFix.asi` stays an old plugin of the part.
2. The harness: `test\fake_dstorage.cpp`'s `OpenFile` opens the file for real with `CreateFileW`, read access and read sharing, and holds the handle, as DirectStorage does; `test\fake_game_full.cpp`'s DirectStorage scenarios then prove the sharing - while the stand-in holds a text file open, the fake opens it for writing while sharing reading (succeeds) and renames it (succeeds), opens it for writing while sharing nothing (the sharing violation, the documented limit); while the stand-in holds an archive, the fake's write open fails as before; a loose file in a subfolder the way a loader serves it (`onigiri\common\data\gameconfig.xml`) is opened, readable and shared; the fake's own exclusive read-only open, a directory open, a path outside the game folder and a `\\?\` path are left alone; `dstorage.dll` not loaded; everything on with `DIAGNOSTIC_MODE`. `test\run_directstorage.sh` is rewritten for them; the check count moves.
3. The documents: README.md's DirectStorage section and the `UNLOCK_FILES` row (what it does now, and the limit for a program that writes while sharing nothing), NOTES.md's DirectStorage bullet and its "Confirmed on 1.0.1158.16" paragraph (re-measured on my boot), SPECIFICATIONS.md 11.8 rewritten, 12 (the rules on hot paths and never silent name the new hook), 14.1 (the stand-in) and 14.2's row, PATTERNS.md's DirectStorage paragraph and item 5 (the premise that the game reads only archives there is gone; the interface and `OpenFile`'s slot stay as the diagnostic facts they are). ROADMAP.md's 2.2.0 entry goes when the version is released.

Then the release: version 2.2.0, a clean rebuild, the suites, my boots - with NVE installed (the game runs with onigiri's loose files served, the summary counts the opens shared, a text file in the game folder can be renamed while I play) and without NVE with my mods folder (served as before) - then the tag.

## 2.2.1 - two parts switch themselves off next to NVE's loader (track 3)

Track 3 ran in parallel with track 1 and is released after 2.2.0. One phase:

1. `TweaksVFeatures.h`, `TweaksVFeatures.cpp`, `TweaksVConflicts.h`, `TweaksVConflicts.cpp`: a second kind of plugin per part, one that does the part's job and stays installed, with a name and a short description for the wording; `onigiri.asi` ("NaturalVision Enhanced's loader") for RageOpenV and StraightToStoryMode, not for DirectStorage (2.2.0 refuses nothing). Found in one of the loader folders while the part is on, it switches the part off for the session like an old plugin and is reported as an item of the start-up summary: `<path> is installed and does this job too (NaturalVision Enhanced's loader): TweaksV's RageOpenV part is switched off while it is there, so nothing is patched twice. To stop this message, set ENABLED=0 under [RAGEOPENV] in TweaksV.ini.` A part already off by its INI reports nothing; a log line says the file is there and the part is off already, so the log always shows what the check found. The old plugins keep their wording and behaviour; the "none found" line covers both kinds.
2. `test\run_integration.sh`: `onigiri.asi` alone in each of the three loader folders - the two parts off with the exact wording, the other six applied, DirectStorage on; together with the old plugins all at once; with the two sections off by their INI, no item. The check count moves.
3. The documents: README.md's "Other mods" (the NVE paragraph: the heap, and the loader with what TweaksV does next to it, where the mods then go, the landing page not skipped unless onigiri's INI does it, the INI switches that stop the message) and "Testing" step 2 (the eleventh file, which stays); NOTES.md's "Conflicts" bullet (the two kinds, and the facts behind this one: onigiri loads before TweaksV but patches at the game's first request for the time, after TweaksV's changes, and faults at its offsets 0x1ea45 with RageOpenV's sites changed and 0x1f2be with the story sites changed, version 1.0.1.0 - what a report to NVE's author needs); SPECIFICATIONS.md 4.3 (the table), 7 (the second wording), 14.2's integration row.
4. Found by the track, fixed with it: the log header's `Features:` line was written before the conflict check ran, so a part the check switched off said `on` there, against SPECIFICATIONS.md 6.2, since 2.0.0 - the check now runs before the header, its lines kept and written after it (6.1), pinned in the integration suite; SPECIFICATIONS.md 3 and 6.2 as built.

Then the release: version 2.2.1, a clean rebuild, the suites, my boot with NVE installed (the start-up summary names onigiri.asi and the two parts, the game runs, onigiri's own skips work) - then the tag.
