## How the work runs

Each version is a track: one coding session in a worktree of its own (the app makes it under `.claude\worktrees\` with a `claude/...` branch), with a prompt from the overview session, kept in `.claude\prompts\` and never committed. A track owns its files and regions, so two tracks never touch the same region of a file; where a line is shared all the same - the check count in NOTES.md and in SPECIFICATIONS.md 14.1, the adjacent rows of 14.2, the RageOpenV row of 4.3 - the overview session resolves the merge. A track commits on its branch only, each item its own commit; it never merges, tags, pushes or sets the version; after every commit it writes its paragraph into the State block below and a two-line report into the chat, and it ends its turn only when the track is done or a decision of mine blocks everything left. The overview session rebases the branches onto main in order, makes the changelog lines and the check count one, sets the version, runs the suites from a clean rebuild, hands me the boot, then tags and pushes main and the tag together. Tracks 1 (2.1.1) and 2 (2.2.0) are released; track 3 is rebased onto main and merged.
